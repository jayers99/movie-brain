# Viewing log contract (brief `docs/superpowers/briefs/2026-09-21-viewing-log/brief-2.md` v2.2, migration 031, built 2026-09-27)

- A viewing is a dated EVENT against a film (`viewing`: film, `watched_on`, optional registry `service`, `logged_on`; `UNIQUE(film_id, watched_on)`); an `artefact` is what he said about it (kind `dictation` only in v1; the CHECK widens by a later migration). The 0–10 stays in `my_ratings`, written through `_write_rating` (the same one-liner `set_rating`'s upsert uses) inside `add_viewing`'s one transaction; nothing on the viewing is a rating. Both `viewing.id` and `artefact.id` are `INTEGER PRIMARY KEY AUTOINCREMENT` (point-C gap check finding 1, migration 031 edited before any real database applied it — legitimate only because the branch is unmerged): a removed id is retired for good, so a repeated or retried `viewings remove N` cannot land on whatever now sits at N.
- `movie-brain viewings add` is the ONLY writer; sync, `enrich` and every import verb never touch these tables; the dashboard reads them (detail-only `viewings`, `old_ratings`; `last_watched` + `viewing_count` on the list payload) and never writes them. The drawer's log has no buttons.
- The title ladder lives in `application/viewings.py::resolve_title`, never in a prompt: rung 1 the film the dashboard reports open (`meta.drawer_film`, a 30 s heartbeat trusted 120 s — `Repository.drawer_film`) when its normalised title equals the dictated one (**only a `--year` he names skips this rung — a director does not**, point-C finding 2: the skill instead confirms the open film with him before running anything); rung 2 exactly one canonical film (no `film_disposition` row) with that normalised title; rung 3 stop (AMBIGUOUS lists the films, NO-FILM lists the nearest titles via `title_hits` over the words minus articles and vs/versus, then a normalised substring) and write nothing, exit 3. One normaliser, both sides, at query time: `domain/thumbprint.py::title_norm`; the `films.title_norm` column is NEVER read (empty for every film created since the backfill). An AMBIGUOUS candidate's director falls back to `Repository.film_credits(film_id).director` when `films.director` is NULL (finding 10, the same fallback the drawer uses) — 1,857 of 5,274 canonical films carry no `films.director`.
- When both `--title` and `--film` are given they must agree (finding 7): `log_viewing` refuses (`REFUSED --film ID is 'Title' (Year), not '<dictated title>'`) unless the dictated title's normalised form equals or is contained in the film's own — a mistyped id in a rerun is caught, never silently logged.
- One viewing per film per day; a second add appends an artefact (`ADDED-TO`), moves the rating if given, sets the service only if the line had none — never overwrites one, and the line now SAYS so when a differing `--service` was given (finding 8: `· service kept: <line's slug> (<given slug> noted)`) via `ViewingWrite.service`, the slug the line ends up carrying. Refusals (`REFUSED`, exit 2: future date, blank text, unknown slug, rating outside 0–10 — parsed by the CLI itself so `--rate 7.5` reads the same REFUSED shape as everything else, not typer's own boxed error — unknown viewing/note (names how many notes the line actually has), non-canonical `--film`, a `--title`/`--film` mismatch) happen before the one transaction and write nothing. Logging clears `unseen` with a bare `DELETE FROM unseen` inside the same transaction — the one-liner `set_unseen(False)` also performs, not a call through it — so nothing else moves; removing restores nothing. `REMOVED` lines name the film's title (finding 1), not just its id.
- `viewings list --film ID` (only with `--film`, finding 3) prints every viewing's notes numbered underneath it (`    note 1  <first 60 chars>…`) — the only place a note's number is readable; the skill reads N off this before any `remove --note N`.
- `merge_film` re-points `viewing.film_id`; a same-date collision moves the loser's artefacts onto the survivor's viewing. A viewed film is always visible in `list_views` (current-or-rated-or-viewed).
- The agent's side is `.claude/skills/log-viewing/SKILL.md`: extraction rules (one film per command; date never invented; service mapped through the film; a rating only when ONE whole number is offered as a rating), what to do on each exit code, the director-confirmation rule above, "after midnight" dating, and which sentences are not viewings at all (an import request, a plan for later, a long piece stored whole as one note). `films add --apply` always waits for the owner's yes.
