# movie-brain

Personal film brain: Criterion Channel listings + OMDb ratings + my 0–10 ratings in SQLite, served by a local Flask dashboard. Successor to criterion-ratings; more `listings.source` values (Apple Movies, …) may be added later.

**Status 2026-09-07:** power search (spec `docs/superpowers/specs/2026-09-06-power-search-design.md`, exact + fuzzy + semantic) is COMPLETE and applied live; follow-up candidates live in `docs/backlog.md`. **Roadmap:** a phased multi-service expansion is planned — before feature work, read `docs/multiple-movie-services.md` (Implementation phases + Data model decisions: GUID identity, immutable films/no purge, Metacritic top-N dial) and `docs/vision.md`. Discovery spike scripts live in `scripts/discovery/`. Sibling project to converge with: yt-brain (see `docs/cinema-companion.md`).

## Commands

```bash
uv run movie-brain sync [--full|--ratings-only]      # refresh catalog + OMDb ratings; keys new films via the thumbprint resolver BEFORE the OMDb loop, which fetches by IMDb id only (unkeyed films are skipped, not title-searched); also refreshes weekly availability
uv run movie-brain metacritic crawl [--pages 10]     # extend the raw browse-page archive (polite, checkpointed)
uv run movie-brain metacritic match                  # offline: match archive → films, report coverage
uv run movie-brain metacritic dial [N]                # show/set the Mode-B top-N; promotion runs in nightly sync
uv run movie-brain owned import                       # AppleScript export of the Apple TV library → mark/create owned films (macOS, never in sync)
uv run movie-brain lists import lists/<slug>.tsv [--apply]   # phase 1 of a curated list: resolve every entry, link what the catalog holds, queue the rest as `list` reviews — NEVER creates a film; dry run by default, prints the full per-entry scorecard; an optional 4th `tt` column is compared against the resolver's own verdict (never replaces it) and scored on a trailing agreement line, a mismatch queuing `id-disagreement`; an optional 5th `year` column (migration 020) is passed to the resolver as a trusted year, which is what lets a director-less title-and-year source resolve
uv run movie-brain lists create SLUG [--apply] [--yes]       # phase 2: mint (born keyed) the films an imported list's still-unresolved entries need — the only creating path, re-resolves and re-gates every entry, dry run by default
uv run movie-brain lists trust [SLUG [N]]                    # show every list's trust (desc then slug), show one list's, or set one (0 legal — visible, scores nothing); the ONLY writer of `film_list.trust`
uv run movie-brain oldratings import PATH [--apply]          # my 2004-08 1-5★ ratings as a WATCHING SIGNAL (never `my_ratings`): store every row of the CSV (it lives outside this repo), link each through the thumbprint resolver + gates 1/2/2b; NEVER creates a film; dry run by default, full per-row scorecard, idempotent (a re-run only links rows still unlinked); `--apply` archives the raw file under <config_dir>/oldratings/
uv run movie-brain oldratings create [--apply] [--yes]      # the only creating path: mints (born keyed) the films my old 4-5★ rows name that the catalog lacks, re-resolving and re-gating every row; 1-3★ never mint
uv run movie-brain oldratings link LINE (--film ID | --none) # the hand path for a row the resolver refused (typo'd title, wrong typed year, ambiguous); `oldratings list [--unlinked]` prints the rows
uv run movie-brain services list | quality SLUG [N] | apple SLUG [0|1] | subscribe SLUG [0|1] | url SLUG [TEMPLATE|-]   # the service registry, best first on the same four keys that rank a film's options; the ONLY writer of `movie_service.quality` (0 legal — ranks last), `has_apple_app`, `subscribed` and `search_url` (migration 021: the service's title-search template with a `{title}` placeholder — where the drawer's "Watch on <service>" link lands; `-` clears it, and with none set the link falls back to the listing's stored URL); a bare slug shows one service, an unknown slug exits 2
uv run movie-brain cheapcharts resolve [--apply] [--limit N] [--recheck [--after FILM_ID]]   # resolve each film's DIRECT CheapCharts product page and store the iTunes id under external_ids authority `itunes`; asks by IMDb id 5 films per call, falls back to a title search only where CheapCharts' IMDb index has a hole (a search answer is believed only when `match_owned` confirms it), stops on a 429; dry run by default, self-checkpointing; --recheck re-asks the API for every STORED id — a product Apple removed comes back titled `[❌Removed from iTunes]` and is re-resolved through the search fallback, the confirmed re-listing REPLACING the dead id in place (owner ruling 2026-09-07; ~12% of 2,368 stored ids were dead when measured); an unconfirmed one is reported and left; `--after` resumes a rate-limited run
uv run movie-brain cheapcharts wishlist [--resolve [--apply]]   # read MY CheapCharts wishlist (login from <config_dir>/credentials.toml, section [cheapcharts]) and replace the dashboard's hearts wholesale from it; never writes to the account; bare verb has no dry run (the dashboard does the same refresh on every start); `--resolve` also places wishlist films movie-brain holds no store id for — one paced DetailData call per unplaced product, joined on the exact IMDb id CheapCharts names — dry run by default (it still refreshes the hearts), `--apply` stores the `itunes` ids; prints counts and titles only, never a price or anything from the account; exit 2 without credentials, exit 1 when the read fails (hearts kept)
uv run movie-brain enrich credits [--apply] [--limit N]     # TMDB cast/crew/characters/keywords/overview for every film holding a tmdb id and no `credits_fetched_on`; one call per film, stamped and resumable, never in sync; dry run by default (power-search spec §5)
uv run movie-brain embed [--apply] [--limit N]              # vectors for the bar's semantic stage: overview + plot + tagline per film (NEVER the title), all-MiniLM-L6-v2 via the optional extra (`uv sync --extra semantic`); stamped + resumable, re-embeds a film re-enriched since; never in sync; dry run by default and needs no extra (power-search Plan C spec §7)
uv run movie-brain dashboard [--port 5556]
uv run movie-brain import-legacy [--from DIR]        # one-shot criterion-ratings import
uv run movie-brain export csv PATH
uv run movie-brain status
uv run movie-brain migrate [--apply]                  # the ONLY path that advances an existing DB's schema; dry run lists pending, --apply backs up + applies; fresh DBs bootstrap on open
uv run movie-brain rematch                            # one-shot repair: rematch TMDB misses, reconcile non-Criterion years (needs TMDB token; idempotent)

uv run movie-brain repair dupes [--apply] [--yes]     # audit norm-title + id-conflict dup groups; --apply merges TWIN groups only (--yes skips the per-group prompt)
uv run movie-brain repair links [--film ID] [--tt ttNNN] [--apply]  # re-validate stored TMDB links against TMDB's title/original_title/alternative titles (one call each); --film audits/clears one link unconditionally; --apply clears suspects; --tt (requires --film) instead RE-KEYS that one film through `key_film` — the case no audit can see, where imdb and tmdb agree with each other but name the wrong work — and clears nothing
uv run movie-brain repair imdb [--apply] [--limit N]  # fill in the IMDb id TMDB already publishes for films holding a TMDB id and no IMDb one; writes the imdb id ALONE through `key_film` (tmdb_id=None, resolve_tmdb_id=False) so no film's year moves; dry run by default, one TMDB call per film, `held` ids queue an `id-conflict` review row
uv run movie-brain repair years [FILM_ID YEAR] [--apply]  # year worklist: open year-collisions + stale OMDb payloads; --apply marks stale rows for OMDb refetch; with FILM_ID YEAR, corrects one film's year
uv run movie-brain repair years --from-tmdb [--apply] [--limit N]  # one-time backlog pass: fills films.year from TMDB for films holding a tmdb id but no year at all; collisions queue year-collision review rows; dry run by default
uv run movie-brain review list [--authority A] [--reason R]   # open match_review rows (filterable)
uv run movie-brain review resolve ID (--film X | --tmdb-id X | --create | --dismiss | --pick A|B|C | --tt X [--series] | --none) [--note]  # standing decision on one review row: link to a film, link a TMDB id, create the staged film, dismiss, key to an A/B/C candidate, key to an IMDb id, or verify unkeyed; a --tt TMDB knows only as TV (or forced with --series) is keyed by IMDb id alone and marked kind=series
uv run movie-brain review revisits                    # films the user flagged "needs revisit" in the drawer

uv run movie-brain repair twins [--apply] [--yes] [--limit N]  # retire raw `Title (YYYY)` films into their same-year twin (contract-checked); --limit = batch size
uv run movie-brain repair editions [--apply] [--yes] [--limit N]  # fold `Title (edition)` films into their same-year work (contract-checked); --limit = batch size
uv run movie-brain repair disagreements [--apply] [--yes] [--limit N]  # repair films whose OMDb imdbID ≠ TMDB imdb_id (eval group D): verified rows applied, proposed rows → A/B/C review; already-repaired films list as pending/review-open and --limit batches only the actionable ones
uv run movie-brain repair nomatch [--apply] [--yes] [--limit N]  # rerun open tmdb no-match films through the thumbprint resolver: matches keyed via record_tmdb_match, non-matches promoted IN PLACE to durable `no-match-reviewed` A/B/C rows (drain with `review resolve --pick/--tt/--none`); --limit batches actionable films only; candidates cached in <config_dir>/nomatch-cache.json.gz (eval fixture never written)
uv run movie-brain thumbprint backfill [--apply]      # copy owned/criterion/metacritic evidence into `claim` rows (pure copy, idempotent)
uv run movie-brain audit run [--no-tmdb]              # read-only consistency checks → audit_flags (+ one-time TMDB facts cache); prints tally + top suspects
uv run movie-brain audit verdicts [--verdict V]       # append-only human verdict history (pattern-analysis export)

uv run pytest                                        # whole suite (~40s, Playwright dominates; the real-model test runs only when the semantic extra is installed, else skips)
uv run pytest -q -m semantic                         # the ONE test that loads the real sentence-transformers model (needs `uv sync --extra semantic`)
uv run pytest tests/step_defs/test_sync.py -k kept   # single test / scenario by keyword
uv run playwright install chromium                   # once, for tests/web/test_dashboard.py
uv run ruff check . && uv run mypy                   # lint + types (mypy also runs as a pre-commit hook)
uv run python scripts/matching_benchmark.py [--assert-dominance]  # matcher regression gate: ground truth + archive replays
uv run python scripts/thumbprint_benchmark.py --assert  # thumbprint resolver gate (offline fixture): 0 wrong on every row + auto ≥ 90% on non-F-human rows
```

## Architecture (hexagonal — dependencies point inward)

- `domain/` — pure, imports nothing else: `Film`, `FilmView`, `film_key`, `merge_yearless`, canned-filter predicates in `filters.py`.
- `application/` — use cases (`sync`, `ratings`, `export`, `legacy_import`) orchestrating through `Repository`; no SQL or HTTP here.
- `infrastructure/` — `config` (env / key file), SQLite `Repository` + `migrations/*.sql`, `criterion.py` (VHX API adapter), `omdb.py`, `tmdb.py` (watch-providers adapter).
- `web/` — Flask `create_app(repo)`, one template; ALL filter/sort logic is client-side vanilla JS in `static/app.js` (virtual-scrolled table, state encoded in the URL) — with ONE exception: the search bar's query is resolved server-side by `GET /api/search` into a film-id set that `app.js` intersects with its own pipeline (power-search spec D4); the id set is the whole interface, and no chip, scope, list or column logic moved. A second page, `/rank` (`rank.html` + `static/rank.js` + `rank.css`, never `app.js`), is the tier ranker.
- `cli.py` — Typer entry point wiring config → `Repository` → use cases.

### Sync flow

Seven-step contract (cheap check → merge_yearless → record_catalog + criterion claims → Mode-B promotion (resolve-first) + metacritic claims → keying (`key_films`) → OMDb by IMDb id only → TMDB providers/notifications) lives in `.claude/rules/sync-flow.md`, loaded when you work in `application/sync.py`, `availability.py`, or `metacritic.py`. Keying runs before the OMDb loop so a film keyed tonight gets its OMDb record by IMDb id tonight; a film with no IMDb id is skipped and counted in `SyncResult.omdb_unkeyed` rather than looked up by title.

## Rules

Path-scoped contracts in `.claude/rules/`: `matching.md` (the one evidence-scored matcher, wrappers, benchmark gate, rerelease/yearless rules), `audit.md` (audit_flags / tmdb_facts / audit_verdict), `thumbprint.md` (the work-identity resolver — live in sync, `owned import` and Mode-B promotion since T5 — its offline gate, the `claim` table now written by every ingester at ingest), `lists.md` (curated top-N lists — the list file, the fallback-only form ladder, the three creation gates plus 2b, and the two-verb split that keeps the import from minting films), `watch.md` (the best-source ranking — its four keys and the tier that is deliberately not one, the Criterion re-join, the single writer of the registry's owner columns, and the accepted Amazon-channel duplication). They load when you touch the files they name — read them before changing matching or audit code.

- Film identity = `films.guid` (generated UUIDv4, immutable once assigned); the integer `id` is an internal join key that must never leak as identity. `film_key(title, year)` is a matching aid and the Criterion upsert conflict target — not the identity.
- Films are immutable: collectors never delete. "Current" = latest `last_seen` per source; "departed" is a pure display state. Unrated departed films stay in the DB, hidden by the current-or-rated view filter; rated departed films are shown as departed.
- `movie_service` is the service registry (slug PK; kind `svod`|`store`; `subscribed`/`region` are data, and since migration 017 so are `quality INTEGER NOT NULL DEFAULT 1` and `has_apple_app INTEGER NOT NULL DEFAULT 0` — the owner's two hand-set ranking constants, written by `movie-brain services` and by nothing else, exactly as `lists trust` owns `film_list.trust`; at the defaults the feature is inert; migration 021 adds a third owner column, `search_url TEXT` NULL, same single writer, not a ranking key). `service_provider` groups TMDB provider ids per service, and `register_provider` auto-creates BOTH rows for any provider TMDB reports that the registry doesn't know, at `subscribed = 0` — `INSERT OR IGNORE` on both statements, naming none of the three owner columns, so a nightly sync can never overwrite a judgement; a provider name that slugifies to empty raises there and is skipped by the caller. `external_ids` maps films to per-authority native ids, PK `(film_id, authority, value)`; `UNIQUE(authority, value)` remains the dedup guard; tmdb/imdb are single per work by policy, claim authorities may repeat.
- Metascores are scraped-first: the FilmView `metacritic` value COALESCEs the scraped `metacritic` table (joined via `external_ids` authority `metacritic` = slug) over `omdb.metacritic`. The raw page archive under `<config_dir>/metacritic/` is the crawl checkpoint — archived pages are never re-fetched; parsing reads only the archive. Match anomalies land in `match_review` (never deleted, never blocking); no scraping in sync.
- Availability lives in `listings`: TMDB writes svod sources from `flatrate`, `free` and `ads` unioned (canon-best-source C2 — all three mean "I can watch this", and reading only `flatrate` threw away 29 of 46 checkable canon films' US availability), plus `apple-tv-store` from rent/buy provider 2; the weekly refresh is gated by meta `tmdb_providers_refreshed_at`. Migration 003's "Amazon-channel ids (1825, 201, 287) and GB BFI Player (224) deliberately excluded" comment is HISTORICAL: auto-registration reverses it, so the registry will come to hold `max` beside `max-amazon-channel` and the like — accepted, not a bug, because `subscribed = 0` contains a duplicate (it can't reach the `reachable` scope, can't move the `acquire` gate, and can't outrank a real option since `subscribed` is the first ranking key).
- Availability transitions are append-only events recorded at listing-write time against the pre-batch currency frontier; `watchlist` is user-response data (drawer toggle is the only writer). "Current" for TMDB-fed sources = `last_seen >= tmdb_providers_refreshed_at` (MAX fallback when no stamp; criterion keeps MAX(last_seen)).
- `_VIEW_SQL` drives from `films` with a LEFT JOIN on the criterion listing (not an inner join) so Mode-B films with no Criterion listing are visible; `list_views` keeps Criterion parity by filtering to no-listing OR current OR rated (unrated departed still hidden). `FilmView.url` is nullable (populated only from a Criterion listing; Mode-B/discovery films are always `None` here) and `FilmView.criterion` is a bool. `FilmView.metacritic_url` is set at match/promotion time and is still populated and served on the API, but since the 2026-09-07 drawer redesign nothing on the client reads it — the drawer's links row is Criterion, TMDB and CheapCharts only; only Python touches the field now — the repository, the model and both test suites. `summary()` stays criterion-scoped plus a `discovery` count — it is the MAINTENANCE view (`movie-brain status`, `/api/summary`); the dashboard header no longer mirrors it. Since 2026-09-07 the header shows four catalogue-wide counts computed in `app.js` from the films payload: films, reachable (the default scope's own predicate, so the number and the toggle cannot disagree), owned, rated by me. The dashboard's old three-way scope toggle is GONE (2026-09-07 chip redesign): its job moved into the Reachable chip, and the default view is every film. **Reachable** means somewhere to watch it today — a current Criterion listing, ANY current listing on a streaming service (subscribed or not) or the Apple store, OR owned (owned is watchable, and ownership on Apple is proof of a store presence TMDB's patchy US data missed: 18 of 28 owned films read unreachable on 2026-09-07 for that reason), OR holding an `itunes` external id (a CheapCharts product page exists only for a title the Apple store sells, and TMDB's provider feed lags new digital releases by weeks — The Odyssey 2026 was buyable on Apple with no TMDB provider anywhere; 23 of 163 unreachable films held one); rated/watchlisted are judgements and do not count. "Not reachable" is the complement. The provider worklists (`films_for_provider_refresh`, `films_for_first_check`, `films_for_watchlist_refresh`) are driven by the film's TMDB id in `external_ids`, never by the legacy `tmdb.found` flag — nine resolver-keyed films the old title matcher had marked not-found sat outside the refresh for two weeks. `domain/filters.py::reachable` and `app.js`'s `reachable` are the same predicate, shared by the header count and the chip. A saved `scope=criterion` URL maps onto the Criterion chip; `scope=all` is the new default. `FilmView.services` entries are `{name, subscribed, kind, quality, has_apple_app}`, ordered by `_SERVICES_SQL` on the same four keys `domain/watch.py::rank_key` uses; the drawer splits them into "Also streaming on:" (svod) and "Buy on:" (store, which also adds a "Find on CheapCharts" search link). `export csv` writes `list_views` unfiltered, so it also includes discovery films (empty `url` cell) — this is intended, not a bug.
- Canned-filter thresholds and chip names live ONLY in `domain/filters.py`; JS reads thresholds from `/api/config`. Keep `CHIP_PREDICATES` in `app.js` and the chip buttons in `index.html` in lockstep with `_PREDICATES`. **The bar (2026-09-07 redesign) is four three-way chips and three plain ones (Rewatch joined 2026-09-19), everything off by default:** Reachable (`reachable`/`unreachable`), Rated (`unrated`/`mine`), Criterion (`criterion` = on the Channel now, departed excluded / `leaving` / `criterion_new` = arrived on the Channel within `NEW_ARRIVAL_DAYS` = 30, "this month" / `not_criterion` = nothing on the Channel now, departed included), Watchlist (`watchlist`), Owned (`owned`/`not_owned`), On a list (`multi_list`), Rewatch (`rewatch` — see Old ratings below), then the list picker and Clear. A cycle chip carries its keys in `data-cycle` and its labels (off first) in `data-labels`; one click cycles off → A → B → off; the keys are ordinary predicates, mutually exclusive only in the UI, so URL state is still just `chips=`. Removed keys (`top_ratings`, `recent`, `pending`, `departed`, `new_arrivals`, `needs_revisit`, `suspect`, `acquire`) are unknown now and dropped from old URLs. `multi_list` (labelled "On a list"; threshold `MIN_LISTS` = 1 since 2026-08-30 — the KEY keeps its old name because it is encoded in URL state) counts `f.lists.length`, not weighted trust, so downgrading a list's trust never drops a film off the shortlist; while it is active the default sort leads with `canon_score` desc (the sort the retired `acquire` chip carried).
- The `acquire` chip ("Canon, not owned") was RETIRED in the 2026-09-07 bar redesign: On a list ✓ plus Not owned reproduces its filter minus the Metacritic ≥ 90 clause, and its canon-score sort moved onto On a list. `canon_score` — `Σ trust × (1 − (printed_rank − 1) / size)`, no membership floor (design D12) — stays defined canonically in `domain/filters.py` and mirrored in `app.js`; `is_canon` stays. `acquisition_candidate` is gone.
- `FilmView.best_source` is the single best place to watch a film today — the first entry of its ranked svod option set (`domain/watch.py::best_source`/`rank_key`), sorted `subscribed DESC, quality DESC, has_apple_app DESC, name ASC`. The monetization tier is deliberately NOT a key (C2), and a `store` is never a watch option. It is **computed on every read and never stored** (C11; the same argument `lists.md` makes for the cross-list tally). Criterion is re-joined into the ranking at the ranking site, from the `criterion` `movie_service` row read once per view build, because `_SERVICES_SQL` filters Criterion out (`l.source != 'criterion'`) and it reaches the read model through `_VIEW_SQL`'s own LEFT JOIN instead — Criterion carries 88 of the canon's 200, so a ranking blind to it would answer the wrong question for 44% of the set. The card badges the winner only when it is subscribed; the drawer links it either way: `best_source` carries `url`, resolved on every read by `domain/watch.py::watch_url` — the service's `search_url` template with the percent-encoded title filled in, else the listing's stored URL (Criterion's direct page, joined per film from `_VIEW_SQL`; TMDB's watch page for provider-fed services), else null. `_SERVICES_SQL` reads `search_url` and `l.url AS listing_url` onto the option dicts ONLY for that resolution; `_row_to_view` strips both (`_PRIVATE_OPTION_KEYS`) so `FilmView.services` entries stay `{name, subscribed, kind, quality, has_apple_app}` and the list payload never carries a URL (drawer spec D10). See `.claude/rules/watch.md`. `movie_service.quality` is a PRIOR over a service's whole catalogue and cannot express a per-title transfer: `observations/presentation.tsv` is the hand-kept log of (film × service) viewing verdicts that records those — no code reads it, and it exists so the eventual schema is designed against real rows. Intolerance (#3096) is its proof case: good on `justwatch-tv` (Cohen restoration), awful on `mgm-plus`, the same night. A single title never moves a service's dial in either direction.
- `_NEW_ON_SQL` and `watchlist_transitions_on` filter on `s.kind = 'svod' AND s.subscribed = 1`: provider auto-registration lands hundreds of services at `subscribed = 0` and each one's first listing write fires an `availability_transitions` row, which would otherwise swamp the new-arrival chip and the drawer's "New on:" line for `NEW_ARRIVAL_DAYS` with services the owner cannot watch.
- `owned` is possession data on the watchlist pattern: `owned import` is the only writer, rows are permanent (never unmarked), and there's no `listings`/`availability_transitions` interaction. Ambiguous matches (candidate ties) and big year disagreements (`year-drift`) queue to `match_review` under authority `apple-tv`, never guessed and never twinned; unmatched owned titles become real films (generated guid) that the existing discovery machinery (OMDb/TMDB) enriches like any other film.
- Year truth-holder: `films.year` is the original release year and importers never edit it on matched films. Precedence when sources disagree: TMDB > a year embedded in an Apple title (`parse_apple_title`) > Criterion (±2) > Apple's track year field (remaster-prone) > Metacritic year (US-re-release-prone) (memo §6). Precedence only means something between two values that both exist — a missing year is not a value worth protecting, so `record_tmdb_match` also writes TMDB's year whenever `films.year` is NULL, regardless of whether the film is commerce-created or holds a Criterion listing; the commerce-only rule still governs when a real year is already present. Director-confirmed matching via the iTunes Search API is the planned upgrade (roadmap parallel track). Exception: a TMDB match on a commerce-created film (no Criterion listing) canonicalizes `films.year` to TMDB's original year and recomputes `key` (`record_tmdb_match`) — write-back never overwrites on a key collision, it queues a durable `year-collision` row in `match_review` as a merge candidate instead. Exactly one holder of the target key does not block: this film's OWN merged-away loser, whose dead key `update_film_year` retires in place (`key || ' #' || id`, since `films.key` is UNIQUE) so its survivor can adopt the year it was holding. Every other holder blocks, under its CANONICAL id — a loser merged into some *other* survivor reports that survivor, so the review names the live identity a human must reconcile. A TOMBSTONED holder blocks as itself: `tombstoned_keys()` is the guard that stops the ingesters re-creating it, and that guard IS the key. `repair years --from-tmdb` is the one-time backlog pass: films holding a TMDB id but no year at all (left over from before the guard was fixed), filled through the same `update_film_year` path, dry-run by default.
- Dispositions: `film_disposition` is the identity ledger written ONLY by the repair verbs. `merged` aliases a losing identity to its survivor — `films_for_matching` returns the loser's title under the ultimate survivor's id (multi-hop chains resolve to the final survivor), so an ingester matching the old title lands on the canonical row; `tombstoned` hides the film and blocks re-creation. Every film read model carries the `_NOT_DISPOSED` guard. `merge_film` moves owned/watchlist/my_ratings/external_ids/listings/omdb/tmdb/availability_transitions rows to the survivor (survivor wins every conflict; when a one-row table's loser value is dropped it's recorded in the disposition note — full row for `my_ratings`/`watchlist`/`owned`, just the loser's `film_id` for `omdb`/`tmdb` since those payloads are large), resolves the loser's open `match_review` rows PLUS the survivor's open rows whose `value` names the loser (the `id-conflict`/`year-collision` counterpart — unrelated survivor rows stay open), and KEEPS the loser's `films` row — collectors never delete. - Power search (Plan B): `domain/search.py` is the pure grammar (`parse_query`: bare run-to-next-field values, quotes legal never required, unknown field → freeform + hint), similarity (`similarity`/`rank_candidates`: token-aware difflib with a named `LENGTH_PENALTY_EXPONENT` (0.35) so a short query embedded in a long name is not over-rewarded — measured `bogrt`→Humphrey Bogart 0.853, `bogrt`→Lena Brogren 0.593 — tiebreak on credit count then name) and the `Filter` type; `application/search.py::run_search` resolves every fuzzy field to EXACT values before any query runs — exact match first, then trigram candidates ranked in Python, the top used only above `CORRECTION_FLOOR` (0.8) and ALWAYS reported in `corrections`, below it `suggestions` and an empty result (D7); a quoted value is exact and never corrected; `title:` is the one fuzzy-looking field that never corrects — it always applies its own substring filter and only ever offers the nearest titles as suggestions when it matches nothing. An unresolvable value inside a repeated field is `0 = 1` *inside its own OR group* (`_filter_sql`'s person/character/keyword/year branches all guard on it) — it never empties the whole AND'd result, so `actor: bogart actor: bacalllzz` still returns Alpha rather than nothing. `Repository.search_films` groups a field's clauses on `(kind, credit_kind, jobs)` — OR within a group, AND across groups, over the whole catalogue (never a post-filter over a top-N, D6) — and scores freeform text across `film_text_fts` (bm25 title 10 / overview 2 / plot 1), `person_fts` (5 for a cast credit billed in the top five, half for six to ten, nothing deeper, never crew — `FREEFORM_LEAD_BILLING`/`FREEFORM_MAX_BILLING`; measured on `marlowe`, 16 of 19 name hits were bit parts or crew, so a freeform name hit is the billing line, while `actor:` stays exact and complete), `character_fts` (4), genre/keyword (3) and a direct `films.title` LIKE (10, so never-enriched films are still found by title): every signal that matches is SUMMED per film, title-weighted — never a precedence where an earlier signal shadows a later one. The FTS trigram index is a candidate GENERATOR only — its own rank is never trusted (on the live index `bogrt` ranks "Ogranya" first). `GET /api/search?q=` returns `{ids, ranked, corrections, suggestions, hints, total}`; `hints` also carries two silent-empty explanations from `run_search` — a fuzzy value too short to correct (`'xy' is too short to correct — try three characters or more`) and a freeform miss on 2+ words (`no film matches all N words — try fewer, or quote a phrase`). `app.js` keeps `state.search = {ids, rank}` and intersects in `rowMatches`, ranks in `compare` only when `ranked` and no column sort is set, encodes `q=` in the URL, and marks `#search[data-settled]` when a response is applied (tests wait on it). The input is `#search.search`, OUTSIDE `#chips`, never `.chip`. Crew-job sets per field live in `FIELDS` and were verified against the live vocabulary 2026-09-06. Known limit: plot text exists only for enriched films (`film_text` is written by `enrich credits`).
- Semantic search (Plan C, spec D14–D21): migration 019's `film_embedding` (`film_id` PK, `model`, `dim`, plain BLOB `vector`, `embedded_on`) holds one vector per film over PROSE ONLY — `embedding_text` joins the non-empty overview/plot/tagline (never the title, D15) — as a plain BLOB rather than sqlite-vec, because brute-force cosine over the whole catalogue measured 0.08 ms per query (D14). `application/search.py::_semantic_stage` runs stage 4 in one of two modes (D16): when the lexical result is non-empty, meaning is one more SUMMED re-rank signal, `SEMANTIC_WEIGHT` 5 × (1 − distance): a ≤ 5 semantic bonus cannot lift a prose-only hit (bm25 overview 2 / plot 1) past a title hit (10); other summed signals (person 5, character 4, genre 3) already could, and that is Phase 1 behaviour, not a change here (D17); when it's empty, the nearest films within the fixed `MAX_DISTANCE` 0.6 (no owner-facing control, D18) become the result, intersected with any field filters. Hearts are also refreshed at every `dashboard` start (`cli._refresh_hearts`; CheapCharts being down never stops the start; the line names how many wishlist films are unplaced and the `--resolve` command — that number never reaches zero, because wishlist films not in the catalogue stay unplaced). `infrastructure/cheapcharts.py` holds the adapters: the public `CheapChartsClient.lowest_price` / `imdb_id_for` over `DetailData.php` (`results.movies` is ONE object; login sends the SHA-256 HEX digest of the password; `itemType` MUST be `buymovies`; token in memory only, one fresh login on a token error). **Answer shapes were learned the hard way: the wishlist READ answers `{results: {ebooks[], movies[], tv[]}, originRequest, responseTimestamp}` with NO `status` key (`idInStore` a string, `customPrice` absent when no target, `initialPriceValue` may be -1) while add / set-target / remove DO answer `status: success|error` — 1,546 green tests and four reviews missed that every read failed, because every fixture had been written from the brief's prose; a fixture for an external answer is built from a real (redacted) answer's shape with invented ids, never from prose.** Secrets: credentials live in `<config_dir>/credentials.toml` (`infrastructure/credentials.py::load_credentials(config, site)`; owner ruling — one file for every site, keyed by site; OMDb/TMDB keys move there as backlog 21); no credential, token, email, customer id or API message may be printed, logged, fixtured or committed — `CheapChartsError` carries OUR wording only, `_failed` maps a `requests` error to its class name and `RateLimited` to `rate limited`, the 502 routes log only that, and `typer.Typer(pretty_exceptions_show_locals=False)` keeps frame locals out of tracebacks.
